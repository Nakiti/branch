In regards to technical regrets, I think there are a few choices I made that limits the long term usability of the application. With long chats that have many diverging branches, the context reconstruction is slow in its current implementation as there is a query per level in the chain. Additionally, multi branch currently requires both branch nodes to share the same immediate parent. It doesn't support branching off a branch and then trying to compare those. 

In regards to feature regrets, I ended up dropping the branch feature suggestion which I intende to implement because I thought it would be inefficient and expensive to implement. The idea would be to suggest branch points in a thread if the conversation devolved from the initial topic, but this would require large LLM calls and be difficult to accurately define what constitutes "off topic"

Something that may have been intersting to implement semantic embedding, where each assistant message could have been represented as an embedding and been used to detect contradicitons between branches. This would have been helpful for branch suggestion as well as you could tell based on how similar the embeddings for messages are to each other whether a new message constitutes a branch. You could then also implement semantic searches across a canvas to find all thread nodes where a particular topic was explored.
